# Bridge experiment log — operational record

Companion to `planning/paper2_evidence_log.md`. That file holds the numbers and what
they mean; this one holds **how each table was produced**, so any result can be
regenerated without guessing.

Read this before re-running anything, and update it in the same commit as any new
experiment.

## Conventions

- Commands run from the instance root, with the instance environment
  (`/home/gep/workspace/femic/.venv` on the lab host). `PY` below stands for that
  interpreter.
- Paths are relative to the instance root unless absolute.
- **`runtime/` is gitignored.** No experiment table, JSON, or derived CSV is committed.
  Every output below is regenerated by the command shown; that is deliberate, because
  a committed output can silently drift from the code that made it.
- `commit` is the code state that produced the recorded numbers. Later fixes are listed
  in *Corrections log* at the end.
- Runtimes are measured on the lab host with `OMP_NUM_THREADS=8`.

**Design.** Whole eligible pool, 177,088 ha treated, 50 ignitions, 480 min, wind 225°,

## X2 — Matched-footprint oracle (E2e, E6, E8)

**Question.** At a fixed footprint with equal treated area, does an arrangement metric
rank the patterns as the fire model does?

**Design.** Fixed footprint grown from a seed block (1,877 blocks, 20,018.95 ha), three
patterns inside it at 20% of footprint area (≈4,026 ha each), 40 ignitions, 480 min,
wind 225°, treated ROS multiplier = `TREATMENT_HAZARD["fb"]` = **0.05**, seed 1.

**Command.**

```bash
$PY scripts/bridge_matched_footprint.py \
  --blocks output/patchworks_ft/fragments/fragments.shp \
  --fuel-types runtime/fire/fbp_stand_curves.csv \
  --topology runtime/ws4/topology_tsa23.csv \
  --footprint-ha 20000 --treat-fraction 0.20 --treatment fb \
  --scenario p90 --ignitions 40 --duration-min 480 --wind-dir 225 \
  --seed 1 --footprint-seed 1 \
  --out runtime/fire/footprint_bridge_fb.json
```

**Outputs.** `runtime/fire/footprint_bridge_fb.json`, plus
`runtime/fire/footprint_bridge_fb_schedules/{barrier,clumped,random}_sched.csv` (the
treated block lists). Runtime ≈ 7 s after the fast solver; ≈ 16 s before it.

**Result.** directed largest reach 471 / 765 / 913 blocks for barrier / clumped / random;
mean 107.3 / 178.5 / 253.2; fire mean 4,833 / 5,250 / 6,088 ha (single seed — see the
corrections log, this ranking did not survive a shared ignition set).

## X4 — Five-seed matched footprint (E7)

**Question.** Does the E2e ranking survive a shared ignition set and seed variation?

**Design.** As X2, but `--seed 1..5` with `--footprint-seed 1` fixed, so the footprint

**Command.**


**Result.** Mean burned unstable (barrier first in 3/5 seeds); barrier best on p90 in
5/5. Directed reach matched the mean ordering in 3/5 only.

## X9 — Legacy verification of E2/E2b/E2c/E2d

**Question.** Do the pre-correction landscape numbers still reproduce, and were they
affected by the ignition confound that invalidated E2e?

**Design.** Re-run the recorded cells through the same CLI path: 50 ignitions, p90,
wind 225°, seed 1, densities 0.1 and 0.2, patterns random/clumped/barrier plus the
continuous band, treated multipliers 0.0/0.05/0.2/0.3/0.4.

**Command.**

```bash
$PY scripts/verify_legacy_evidence.py            # re-runs all 32 cells
$PY scripts/verify_legacy_evidence.py --reuse    # compares against existing JSONs
```

**Outputs.** `runtime/fire/legacy_{density}_{pattern}_{factor}.json`,
`runtime/fire/legacy_grid.csv`. Runtime ≈ 5 min for the full grid.

**Result.** PASS — 19 recorded cells match within 1.0 ha on both mean and p90.

**Why they were not affected.** `landscape_spread.py` builds one block table and picks
the ignition draw from `(block_ids, seed)`. The pattern only changes `treated` and
`ros_eff`, not the table or the seed, so every pattern sees the same ignitions. The
confound was in `bridge_matched_footprint.py`, which created a fresh `default_rng(seed)`
per pattern *after* advancing it for the footprint.

**Qualification.** All of E2-E2d are p90-weather results. E9/E10 show the ordering
reverses at median weather, so they are correct as stated and wrong if generalised.
