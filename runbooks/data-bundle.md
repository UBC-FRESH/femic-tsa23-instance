# Runtime data bundle

Purpose: give a person a working model without a Patchworks rebuild. The repository
tracks code only — `runtime/` and `output/` are gitignored — so a clean clone cannot run
an analysis until these inputs exist.

## What is in the bundle

| path | why |
| --- | --- |
| `output/patchworks_ft/fragments/` | the fragment inventory (the block geometry every analysis reads) |
| `runtime/ws4/topology_tsa23.csv` | block adjacency, 410,823 edges |
| `runtime/fire/fbp_stand_curves.csv` | stand-scale FBP curves per AU, scenario, state, age |
| `runtime/fire/fwi_scenarios.csv` | the fire-season weather ladder (10 quantiles) |
| `runtime/fire/bridge_{pattern}_{sched,blocks}.csv` | the three published bridge patterns |
| `runtime/ws4/compiled_fb_haz/` | compiled WS4 dataset with FB and the hazard feature |
| `runtime/ws4/compiled_sf/` | the full treatment set: CC, FT, FB and SF |
| `runtime/ws4/compiled_ft_econ/` | compiled WS4 dataset with the FT economics layer |
| `runtime/fuel_ft_proto/` | study targets, the capped FT schedule, patch/spatial specs |

Size: 85 MB compressed, about 200 MB unpacked.

## Build it

From the instance root, after a successful rebuild:

```bash
tar -czf tsa23-runtime-bundle.tar.gz \
  output/patchworks_ft/fragments \
  runtime/ws4/topology_tsa23.csv \
  runtime/fire/fbp_stand_curves.csv \
  runtime/fire/fwi_scenarios.csv \
  runtime/fire/bridge_barrier_sched.csv \
  runtime/fire/bridge_clumped_sched.csv \
  runtime/fire/bridge_random_sched.csv \
  runtime/fire/bridge_barrier_blocks.csv \
  runtime/fire/bridge_clumped_blocks.csv \
  runtime/fire/bridge_random_blocks.csv \
  runtime/ws4/compiled_fb_haz \
  runtime/ws4/compiled_ft_econ \
  runtime/fuel_ft_proto
```

## Use it

```bash
git clone https://github.com/UBC-FRESH/femic-tsa23-instance.git
cd femic-tsa23-instance
python3 -m venv .venv && . .venv/bin/activate
python -m pip install -r requirements.txt
gh release download data-2026-10-21 --pattern 'tsa23-runtime-bundle-2026-10-21.tar.gz*'
sha256sum -c tsa23-runtime-bundle-2026-10-21.tar.gz.sha256
tar -xzf tsa23-runtime-bundle-2026-10-21.tar.gz
python scripts/check_spread_equivalence.py \
  --cases runtime/fire/bridge_barrier_blocks.csv --ignitions 20
```

`PASS` means the environment and the data agree with the recorded results.

## What it does not contain

- Source layers (VRI, SiteProd, TSR). Those are inputs to a rebuild, not to an analysis.
- The Python environment. `requirements.txt` builds it; `cffdrs` comes from git because
  it is not on PyPI.
- `runtime/evidence/` and the per-experiment outputs. Those are regenerated by the
  commands in `planning/bridge_experiment_log.md`.

## Provenance

of WS4 alongside any copy you publish, because the WS4 datasets are compiled with WS4's
